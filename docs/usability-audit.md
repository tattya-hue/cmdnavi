# cmdnavi v1.1.0 操作性調査

対象コミット: `401ee2e`（`v1.1.0`）。調査日: 2026-10-17。

## 結論

サブコマンド・カテゴリ・登録済みコマンドに対する補完は未実装。
対話画面には入力による検索・上下キーによる選択があるが、Tab補完とは別機能である。
日常利用で重要な入力編集・貼り付け・検索条件の一貫性にも改善が必要。
特に、登録フォームで矢印キーや複数行入力を使うと意図しない内容が保存される点を先に修正したい。

## 調査方法と限界

- CLIの引数処理、対話画面、登録・編集フォーム、保存処理、コピー処理、READMEとテストを確認。
- Linuxでv1.1.0の実行ファイルを使用し、一時ディレクトリの設定で再現確認。利用者の実データは変更していない。
- 疑似端末でTab・左矢印・日本語検索・外部プロセスからの登録を確認。
- 現在の38件のRustテストと既存の疑似端末スモークテストは成功。
- Windows向け分岐はコード調査。今回Windowsの実端末、Zsh/Fish/PowerShellの個別設定やIME操作は実機検証していない。
- 利用者のシェルに独自補完が入っている可能性はあるが、cmdnavi自体は補完機能を提供していない。
- ユーザーテストや大規模データでの性能測定は未実施。操作負担の評価は実装と再現操作に基づく。

## 補完の対応状況

| 操作場所 | 期待する操作例 | 現状 |
| --- | --- | --- |
| シェル: サブコマンド | `cmdnavi a<Tab>` → `add` | 補完スクリプト・生成コマンドともにない |
| シェル: カテゴリ | `cmdnavi net<Tab>` → `network` | 保存カテゴリをシェルへ返す仕組みがない |
| シェル: サブコマンドのカテゴリ引数 | `cmdnavi edit net<Tab>` | 文脈に応じた補完はない |
| シェル: 登録済みコマンド | 登録済み項目を候補表示して選ぶ | 専用の補完と、選択した項目を指定して参照・コピーするCLI引数がない |
| 登録フォーム: カテゴリ | `net<Tab>`で候補確定 | 名前入力または`#番号`入力のみ |
| 登録フォーム: コマンド | 既存のコマンド・入力履歴から選ぶ | 行読み込みのみ。履歴・補完はない |
| 対話画面 | 検索語のTab補完、候補確定 | 文字入力で絞り込み、↑↓で選択。Tabは無視される |

根拠: `src/cli.rs:37`以降の引数処理、`src/cli.rs:339`以降の`read_line`、
`src/interaction.rs:8`のフォーム入力、`src/browser.rs:87`のキー処理。
依存関係・配布物にもシェル補完用の実装はない。
実行ファイル名そのものやファイル名の補完がシェルで使える場合でも、上記の補完とは異なる。

## 再現できた問題

### 1. 登録フォームの矢印キーがコマンド本文になる（最優先）

疑似端末で`cmdnavi add forms`を実行し、コマンド欄に`ip`、左矢印、`Z`、Enterを入力した。
意図する編集結果は`iZp`だが、実際には以下が保存された。

```yaml
forms:
- command: "ip\e[DZ"
  description: description
```

フォームは`BufRead::read_line`を呼ぶだけで、カーソル移動や入力履歴を扱う行編集機能がない。
対話画面の表示では制御文字を空白にするため、保存された本文と画面上の見え方も異なる。

改善: 登録・編集フォームに行編集を導入し、左右・Home/End・Delete・履歴・候補選択を扱う。
そのうえで、意図しない端末制御文字の保存を防ぐ。

根拠: `src/interaction.rs:8`、`src/cli.rs`の`read_line`、`src/browser.rs:178`。

### 2. 複数行の入力が別フィールドに分かれて保存される（最優先）

`cmdnavi add pasted`へ次の3行を入力すると、正常終了した。

```text
echo first
echo second
real description
```

保存内容はコマンドが`echo first`、説明が`echo second`となり、最後の説明は使われない。
パイプ入力で再現。フォームも同じ行読み込みを使い、対話画面からフォームへ移る際には
ブラケット付き貼り付けを無効にするので、複数行貼り付けの境界も保護されない。
YAML編集や引用したコマンド引数では複数行を保存できるため、保存形式の制約ではない。

改善: 貼り付けをひとまとまりで受け取り、複数行コマンドとして表示するか、保存前に確認する。
非対話入力を対話フォームへ流す使い方と、一行登録の引数も区別して案内する。

根拠: `src/interaction.rs:85`と`:94`、`src/browser.rs:29`と`:97`。

### 3. CLIと対話画面で複数語検索の結果が異なる（高）

カテゴリ`network`に`ip addr`を保存した場合:

```text
cmdnavi --search "network addr"  → No matches
対話画面で network addr と入力 → 1 matches
```

CLIは検索文字列全体の連続部分一致、対話画面はカテゴリ・コマンド・説明をまたいだ語ごとのAND検索。
同じ内容を探しても入口によって見つかったり見つからなかったりする。

改善: 検索ロジックを共有し、両方とも語ごとのAND検索に揃える。

根拠: `src/cli.rs:205`、`src/browser.rs:51`。

### 4. 作成できるのに通常のカテゴリ表示で開けない名前がある（高）

```sh
cmdnavi add -ops pwd  # 成功
cmdnavi -ops         # unknown option で失敗
```

カテゴリ検証が先頭の`-`を許可する一方、トップレベルの引数処理はオプションとして扱う。
対話画面や`edit -ops`では利用できるが、案内される`cmdnavi <category>`で参照できない。

改善: 既存データを考慮した名前検証と、明示的なカテゴリ表示構文または`--`区切りを用意する。

根拠: `src/model.rs:35`、`src/cli.rs:63`付近。

### 5. 対話画面の検索欄で途中編集できない（中）

`ip`、左矢印、`Z`の順に入力すると`ipZ`になる。左矢印は無視され、文字は常に末尾追加。
Home/End・Deleteもなく、修正は末尾のBackspaceまたはCtrl+Uによる全消去に限られる。
長い検索語も先頭から切り取って表示するため、新しく入力した末尾が見えなくなる。

改善: 検索カーソルと横スクロールを実装し、通常の入力欄として編集できるようにする。

根拠: `src/browser.rs:155`以降、`:185`、`:274`。

### 6. 別プロセスで登録しても対話画面へ反映されない（中）

1件の登録がある状態で対話画面を開き、別プロセスからもう1件追加した。
Ctrl+Uで再描画しても表示は`1 matches`のまま。
設定は起動時と画面内の登録・編集後にしか再読み込みされない。

改善: 再読み込みキーを設け、可能なら設定ファイルの変更を検知して選択を保持したまま更新する。

根拠: `src/browser.rs:69`、`:131`。

### 7. 説明を省略した重複登録が予想外に入力待ちになる（中）

説明付きの`ip addr`を登録した後、`cmdnavi add network "ip addr"`を実行すると
説明を空に置き換える確認に入る。標準入力がEOFなら終了コード1になることも確認した。

改善: 説明の「省略」と「明示的に空に変更」を区別する。
省略時は既存説明を維持し、非対話利用時の更新・キャンセルも明示的に指定できるようにする。

根拠: `src/cli.rs:71`以降、`src/interaction.rs:126`以降。

## コード・画面設計から分かった操作負担

| 優先度 | 箇所 | 現状と影響 | 改善の方向 |
| --- | --- | --- | --- |
| 高 | シェル補完 | サブコマンドもカテゴリも覚えて入力する必要がある | Bash/Zsh/PowerShellで文脈に応じた補完。Fishも提供対象に検討 |
| 高 | 登録フォーム | カテゴリは全一覧から名前または番号を入力。候補を絞れない | 入力で絞り込み、↑↓とTab/Enterで選択し、新規作成も同じ流れにする |
| 中 | 項目編集 | 現在値は表示されるが入力欄に入らない。1文字の修正でも全文を入力し直す | 現在値を入力欄へ入れ、その場で修正可能にする |
| 中 | 項目指定 | 通常のカテゴリ表示と検索結果に番号がなく、`edit network 1`の番号が分かりにくい | 表示と編集で識別方法を揃える。将来の補完には安定したIDも検討 |
| 中 | コピー | 対話画面のEnterのみで、CLIから特定項目だけをコピー・出力できない | 項目を指定してコピー／本文だけを出力する操作を提供 |
| 中 | コピーの待ち時間 | 外部コピープログラムの終了を同期的に待ち、タイムアウトがない | タイムアウトと失敗理由の表示。処理中でもキャンセルできるようにする |
| 中 | WSL/SSHのコピー | Linux側は`wl-copy`/`xclip`/`xsel`のみ。WSLの`clip.exe`やSSH端末向けの経路はない | 対応環境の判別と代替方法を整理。今回実環境でのコピー可否は未検証 |
| 中 | 小さい画面 | 36列で動くが操作案内は切り取られ、Ctrl+Eなどが見えない。エラーも2行で打ち切る | 幅に応じた案内と、全文を確認できるヘルプ・エラー表示 |
| 中 | 削除・分類変更 | 対話画面から削除できず、カテゴリ名変更や項目移動はYAML編集が必要 | 選択中の項目から編集・移動・確認付き削除をまとめて扱う |
| 低 | 取り消し・バックアップ | 削除前の確認と競合防止はあるが、成功した削除や編集を戻せない | 取り消しまたは世代バックアップ |
| 低 | 操作の統一 | 中止がEsc、`/cancel`、`q`、Enterなど操作ごとに異なる。フォームから戻る際にも追加のEnterが必要 | 共通の中止方法と保存後の画面復帰を整理 |
| 低 | 案内と言語 | ヘルプは操作別の詳細ではなく共通表示。UIは英語、READMEは日本語 | 操作別ヘルプ、画面内ヘルプ、日本語表示の要否を整理 |
| 低 | 登録数が増えた場合 | カテゴリ名順・登録順と部分一致検索のみ。最近使った項目・お気に入り・あいまい検索はない | 実利用で必要性を確認して優先度を判断 |

関連箇所: `src/interaction.rs:20`、`:197`、`src/cli.rs:145`、`src/clipboard.rs:33`、
`src/browser.rs:306`、`:357`、`:361`。

## 既に使いやすくなっている点

- 一行登録とカテゴリ選択からの登録を選べる。説明は省略可能。
- 日本語の説明も検索でき、対話画面ではカテゴリをまたいで絞り込める。
- 同一カテゴリ内の重複確認、削除の確認、入力中止がある。
- 不正なYAMLを保存せず、編集ファイルを保持して修正を再開できる。
- 保存時のロックと競合チェックがあり、別プロセスの変更を不用意に上書きしない。
- 対話画面は終了時に端末状態を復元し、本文は表示用に制御文字を除去する。

既存のテスト成功はこれらの基本動作を裏付けるが、Tab補完・フォーム内の矢印キー・複数行入力の
フィールド混入・CLIとの検索一致・外部更新の反映は現在のテストでは保証されていない。
`tests/cli.rs`全体はUnix限定で、Windowsのプロセスレベルの共通操作は`tests/portable.rs`の2件に限られる。

## 改善を進める順番と完了条件

1. **入力を意図どおり保存する。** 登録・編集を共通の行編集へ移し、矢印キーと貼り付けで制御列や別項目が混入しない。既存値を直接編集できる。
2. **補完で記憶・入力の負担を減らす。** シェルのサブコマンド・オプション・保存カテゴリの補完を提供し、フォームでも候補選択を可能にする。
3. **登録済み項目を選びやすくする。** 参照・編集・コピーの項目指定方法を揃え、番号やIDにコマンドと説明を添えた候補を表示する。
4. **探した結果を統一する。** CLIと対話画面で同じ検索語が同じ項目を返し、検索欄の途中編集と更新操作を整える。
5. **利用環境で操作が詰まらないようにする。** コピーの待ち時間・WSL対応・狭い画面での案内を検証する。

補完には静的候補（操作名）だけでなく、設定から取得する動的候補（カテゴリ・項目）が必要。
静的な補完ファイルを追加するだけでは登録直後のカテゴリやコマンドは補完できない。
新規のカテゴリ名を自由入力する経路も残し、補完のためにシェル設定を無断で書き換えない。
登録コマンドは空白・引用符・改行を含むので、候補の表示文と実際に挿入する値を分ける必要がある。
現在のCLIに`cmdnavi network <command>`という引数はないため、全文をその位置へ挿入する補完だけを追加しても利用できない。

今回は調査と本レポートの追加まで。アプリケーションの動作、公開済みのタグ・リリースは変更していない。

## 開発版での対応状況（追記）

上記はv1.1.0の調査記録。今回の開発版では以下を実装・検証した。

- Bash/Zsh/Fish/PowerShell向けの動的補完。引数の位置で操作名・カテゴリ・そのカテゴリの項目を区別する。
- 説明欄・検索語・移動先カテゴリに登録済みコマンド候補を出さない回帰テストを追加。
- フォームの行編集・既存値の入力済み表示・欄に限定した履歴・複数行貼り付け。制御列や余分な行入力は保存前に検出。
- CLI/対話画面の検索ロジックを共有。検索欄の左右・Home/End・Deleteと日本語の文字幅を考慮した横スクロール。
- 項目番号付き表示と、番号・登録済み本文による一貫した項目指定。`--show`で先頭が`-`のカテゴリにもアクセス可能。
- 説明を省略した重複登録は既存説明を保持し、入力待ちに入らない。
- `--print`、`--copy`、項目移動、カテゴリ名変更・削除、1段階の取り消し・やり直し。
- 対話画面からの削除・移動・カテゴリ名変更・取り消しと、保存ファイル変更の自動反映。
- コピーのタイムアウト、対話画面での非同期処理、WSLでのWindows PowerShellへのフォールバック。
- F1でスクロール可能なヘルプ・エラー全文。狭い画面の案内と、操作がない間の不要な再描画を改善。
- 補完ファイル・設定方法を配布アーカイブに同梱し、各シェルのテストをCIへ追加。

入力補助の設定方法と候補の区分は[補完・入力編集](completion.md)に記載した。
既存データとの互換性を維持し、永続的な項目IDの追加は行わず、本文による指定と保存時の競合検査を利用する。
お気に入り・最近使った項目・誤字を許容する検索・UI全体の翻訳は、調査時に挙げた拡張案として残る。
